# 地图进入房间与恢复（TASK-4.21 / TASK-103.6）

## R · 需求

地图上的合法点击产生一次进入请求。玩家在重工作开始前获得反馈，房间在主要内容准备完成后接受输入。营地为首测路径，共用入口也覆盖商店、事件、普通战斗、精英、首领和宝箱。返回地图、营地锻造、商店货架、奖励与牌组继续遵循现有页面或局部交互规则。

取证基线为 Release `ae8343ef7f9cc42bb179f56cb613b8d10dc61783` 和 Develop `d7ae494a3136b2f4f707428fefeeae478c6e0495`。Release 已实现 #832 的零退场地图重绘、单次房间绘制和商人按需展开，#825 的恢复入口门禁以及 #839 的共享淡变与其他交互。Source 里仍可见地图点击同步执行 `Nodes.enter`，营地／事件／商店的 `stayOpaque` 和 `finishMapRoom` 省略淡变。两类现象分别通过进入成本和反馈时序验证。

参考固定在 `aeubanks/sts@319009d5`。`MapRoomNode` 确认节点后开启渐暗，`AbstractDungeon` 更新转场并调用房间 `onPlayerEntry`，`RestRoom` 同步创建 `CampfireUI`，场景和游戏绘制渐变。本站沿用已有主题与就绪协议，按可交互目标校验时长。

## E · 状态所有权

- Run、Map、Nodes 继续持有路线、楼层、随机流和房间效果，在 `Nodes.enter` 中原子提交。
- GameUI 的请求记录本次意图与来源身份。提交前核对当前 run、map、楼层、节点、房间代次与转场归属。MapUI 分辨同步提交与异步受理。
- PageReveal 持有遮罩、输入门禁、epoch、慢等待和发布。原生控件及美术 owner 继续负责各自准备、进展和释放。

## A · 方法

先提交轻量反馈，跨出当前输入回调后推进淡出。在遮挡后的独立调度轮执行原子进入，并依据目标页 readiness 揭幕。计时报告分别记录调度、脚本/控件写入、可见画面及输入启用。PC／手机首个可见反馈目标为 P95 ≤ 100ms。

正式精修布局、`nativePageLifecycle=true`、Fengari Host 的五个基线营地样本中，点击回调 P50 106.1ms、最大 161.8ms，核心进入 P50 88.0ms、最大 136.9ms，`Map.restore` P50 80.4ms，其中 `Map.generate` P50 76.2ms。这个样本量下 P95 由最大值主导。冻结同夹具指标为核心 P95 ≤ 35ms 且降低至少 50%，点击至输入启用的回调墙钟合计 P95 ≤ 80ms 且降低至少 30%，60Hz 调度时间 ≤ 300ms。官方设备点击至完整可交互 P95 目标为 ≤ 350ms，设备改善幅度需取得同条件改前样本后核实。旧快路径省略淡变，需如实报告新增的调度时间。

短切换沿用现有主题曲线，房间淡出和淡入各取主题快速时长的一半。提交后的准备等待约 400ms 后显示轻量提示。连续 4 秒没有有效进展或累计 12 秒等待时允许恢复，3 秒测试样本应能自然完成。有效进展来自同一 epoch 内完成的工作；超时只能在线程归还后处理。提交前恢复源地图，已提交后恢复同一房间表现或进入安全菜单。

源地图生成在同一 seed 和章节内复用一个私有条目，缓存只含生成器的几何与随机快照。每次仍校验配置和祖母绿上下文，创建独立地图，重放合法路线并比较完整快照。地图点击使用现有可选节点和点击命中身份，避免为已知可选节点再构建整张视图。保留房间的单次绘制和未展开列表的按需渲染。

## S · 结构

保持现有平铺 Lua 模块。MapUI 接收节点意图，GameUI 将请求绑定到本轮，PageReveal 调度并门禁，`abyss_ui` 注入时间和资源进展。营地、商店和其他房间继续使用现有 NodeUI、资源 owner 及生成布局。

生成布局核对使用正式精修美术与原生页面生命周期配置。正式 RC 构建关闭实验性的原件组件、动态卡图与 V25 卡面／遮罩，仍挂载批准的选角／战斗肖像和 42 个精修怪物资产。记录的布局配置只能证明本次源码夹具采用相同入口。正式候选缺少 Production 底图和官方回执，实际试玩 SHA、buildId、GIL SHA256 与 payloadDigest 仍待核对。

商店房间显示商人后，货架已按商品分批准备并有「正在展开」提示。营地锻造使用现有可复用牌面与局部选择界面，奖励选择和牌组分别使用既有局部保护。回图使用同一 PageReveal 的跨页发布。检查这些入口的输入和复用回归，避免新增全屏闪黑。

## O · 操作

先采集精确基线，再用同一 seed、布局、流程和测量范围重跑候选。离线使用生成布局、真实 Host 和按钮，模拟 250ms／1s／3s、永久 pending、明确错误与同轮长同步调用。保留无转场 Host、输入取消、迟到提交、回图和相邻局部交互回归。官方验收绑定 source SHA、buildId、GIL SHA256 和 payloadDigest，并记录实际配置、录像、冷暖条件与设备。

Release 按 PR-only 管理员路径核验当前 Ruleset、账号、独审、精确 HEAD／BASE／tree 与检查结果。Develop 只回流相关切片，按独审、Required Checks 和队列核验实际落点。

## N · 观测

按进入请求记录输入、反馈提交、核心进入、投影、原生准备、就绪和输入启用。首帧和完整帧以渲染回执或录像测量。离线报告记录条件、样本数、P50／P95／最大值、最长同步段与资源计数，保留不利结果。

## S · 保护

覆盖连点、旧触点、迟到 ready、取消、菜单进入、缩放与销毁。准备期间只允许安全恢复；已提交进入只执行一次。验证同种子路线、随机、入场效果和奖励，并保留既有画质、资源预算、事务和检查断言。
