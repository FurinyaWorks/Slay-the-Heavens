# PC18：默认地图是计数，默认战斗才复现两瓶相同

**对前一轮表述的校正。** 前次函数级探针显式传 `mapSlots=true`，证明默认构建里的潜在槽位若显示会回退到同一图集；它不代表实际默认页面会显示这些槽。真实 `refreshPotionEntry` 仅在 official 或 V25 地图锚点满足时启用物理槽。

在[当前九切片离线组合](../current-product-composition/CURRENT-PRODUCT-COMPOSITION.md)上，经实物默认布局 `game-ui.json`（SHA256 `6d4c5f83c986c546ca6cfb21c60a6b7dc0dfac11f278e65f74f54f7ee6963b55`）和真实 Lua Host（native 控件模拟）执行：
1. 地图四态都只显示「药水 2/3」，每态五个物理槽都隐藏。
2. 点开现有管理窗口，两个物理槽名称分别显示「力量药水」与「肌肉药水」；开窗不改药水对象或槽位。
3. 关窗口进入实际第一场战斗后，两瓶均可见，四态均绘制同一图集 `111046`、同一色调，没有 `bottleArt`；两瓶内容未消耗或交换。同时可见的默认战斗短名是「力 / 肌」，所以**瓶图相同不等于完全无法区分**。火焰药水虽同图集，但有既有不同色调，不适合作为最强对照。

## 变更规模不是零

沿用原画法如果真的在地图引入四态 5 槽图池，会新增 **200 image + 20 container = 220 控件**；若叠原题标原型的 416，合计 636（还不含其它页面，不是包容量）。结构原型中状态外共享池只要 55，但**并非即插即用**：pressed 父级 0.96 缩放不会继承，外槽中心最大偏 3.36、瓶宽16应缩到15.36；现 `Art.paint` 找同级 pool；移动后还须验证默认隐藏、原生裁剪、输入透传与回退所有权。[结构和裁剪边界](SHARED-POOL-BOUNDS.md) · [数值](shared-pool-geometry-proof.json)。缓存命中仍调用两次可见性设置，不能把结构少 165 自动折算为帧率或实际平台负载。
