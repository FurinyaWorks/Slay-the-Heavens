# Boss 地图图标生产标准

本标准仅覆盖地图上的 Boss 图标和指向 Boss 的路线终段。保留既有节点位置、点击区域、图例、资源栏、普通节点、非 Boss 连线、滚动及裁切行为。地图规则、可走路径、战斗分别沿用当前模块，不从图标或几何数据推断。

## 图形与预算

生产数据：[map-boss-ink.json](../../data/presentation/map-boss-ink.json)。下表的 ID 是既有 Boss 图标的对应身份，不是拟合所需的新图库资产。图元只用千星原生矩形、圆与三角形（图库 100001、100002、100003），实色深墨 `#233237`、淡墨 `#D9C49C`，不引入位图、渐变、纹理、细描边或额外遮罩。以整块剪影与负形表达；同一视觉框允许各图的非标准圆形轮廓，不为补齐预算增加控件。以地图实际尺寸辨识优先，不按放大图像素误差定档。

| Boss | 既有图标 ID | 可见图元 | 必须保留的识别特征 |
|---|---:|---:|---|
| 深渊守卫 | 112046 | 20 | 左右双角、独立额心菱形、Y 形主干、两侧翼的深色分缝 |
| 六焰幽核 | 112028 | 20 | 内外分层、四角星核心、断开的外围瓣块 |
| 巨型凝胶君王 | 112004 | 18 | 多瓣王冠、圆润胶质身体、两枚深色竖眼 |
| 磐岩斗魁 | 112018 | 20 | 向外张开的大角、重颌面甲、下缘分块 |

深渊守卫 10 图元档容易退化成通用长矛形；30 档的新增细切面在实际地图尺寸收益有限。以 20 档为统一上限。全地图共享 **1 个图标宿主 + 20 个原生图片控件**，不是六份宿主；每次只填充当前 Boss 的槽位，隐藏其余槽位。槽位不接收鼠标、触屏或导航事件，原节点热区仍然负责输入。换图只在显示身份变化时重新填充池，不在滚动和逐帧更新中重复创建控件。未知 Boss 仍走既有图标；图标隐藏、地图重开、换幕或离开视口时不得留下残影或占用额外槽位。

## 底部连线

保持所有真实 `nextIds`，只重绘指向采用新图标的 Boss 的路线终段。按来向从左到右稳定排序，在共享视觉框的底部区域分配入点，沿图标中心轴下方切入；最后一段向上，不从两侧横插，不穿过任何图元，也不互相交叉。终点与实际墨块留小间隙，不以控件矩形边缘代替剪影。在源节点附近保持原路径方向、裁切、虚线池、状态和层级；视口切边、同列和左右来路数量变化不得破坏下方入点。实验的三路场景测过，但不能把该场景的坐标、视口或来路数量写死为通用规则。Boss 离开的路线不属于本次改动。

## 重现与验收

改图先编辑 [96px 矢量母版](../../scripts/art/map-boss-ink-source.json)（不提交原图位图），再用现有单轴三角位姿求解器生成固定精度的生产数据：

```sh
python scripts/art/build-map-boss-ink.py --write
python scripts/art/build-map-boss-ink.py
```

第二条只校验，不改文件。每次更新母版后重新做地图尺寸比对、控件计数和配对 GIL 实测。

1. 在干净工作树运行 `npm run build:data`、`npm run build:ui`，记录源码提交和工作树状态；分别检查正式控件树与 Lua 生成数据。确认图形记录对应六个 Boss，图元类型和颜色受限，计数与上表一致。记录共用宿主 ID、池槽位数、实际可见数量和非交互属性。
2. 用 BeyondSimulator 0.5.2 做同一个真实地图种子、同一滚动位置、同一台架和相同画布的前后读回。保留整张图和终端局部；在同一宿主逐一切换六图，确认仅尺寸和图形数据不同的槽位变化，图例、节点、非 Boss 连线逐项不变。核对截图没有图库占位、共享路径不会穿图，并测试可见、隐藏、重开、换幕、缩放及终端被裁切。模拟器不是官方设备验收。
3. **GIL 容量按同底包成对实测。** 用相同底包 SHA-256、同一构建器与编码器、相同地图内容/选项、相同裁切和路线；只切换无图标基线、同档空池、单一图形数据、六图数据。记录各包实际字节、原始 GIL SHA-256、底包 SHA-256、素材与脚本读回、图元/控件实际数量、可见峰值。用 `带六图的 GIL - 无图标的配对 GIL` 算整个方案；用 `单图的 GIL - 同档空池 GIL` 算单款数据边际。六款边际不能用来替代实际完整包；不能把 JSON、GIA、压缩包体积或单张截图当 GIL 增量。正式工程可能因现有控件与脚本序列化不同而变化，必须在正式构建输入上重测。
4. 如有正式设备验证窗口，导入隔离工程，至少复核一个多来路 Boss 的实际地图截图、滚动裁切和原热区；不能用模拟器截图、示例包字节或离线读回冒充官方导入、实机性能或关卡容量。参考来图、私审截图、渲染 PNG、样例 GIL 与二进制读回附件留在实验评审材料，不写入生产仓库；只提交必要的图元数据、运行时、回归测试及本标准。

独立实验使用 35,795 B 的千星客户端脚本样例作相同底包。其无图标地图基线为 259,444 B；守卫 10/20/30 档总增量分别为 **9,062 / 17,178 / 25,259 B**（同档空池上的图形数据增量 **475 / 991 / 1,471 B**）。共享 20 槽宿主的六图完整包为 280,875 B，较无图标基线 **+21,431 B**，较同档空池 **+5,244 B**。这些数字是该实验的原生离线序列化读回值，不是正式 Release 构建或真机容量指标。
