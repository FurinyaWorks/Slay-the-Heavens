# 怪物大色面量产机制（艺术方向已确认，运行接入待办）

2026-11-16 Owner 确认：以对照的上一档作为判断基线，草史莱姆 **44 控件／41 图元**、遗迹守卫 **119 控件／115 图元**；36／110 过度精简，保留作反例，不继续追数字。此确认指外观与方法；两档是实际原生绘图控制器的离线计数，不是生产游戏性能或发布通过。适用 TASK-25.3 的后续怪物，不套用到角色。

## 1. 每只怪物的输入与预算

- **从实际敌人开始。** 查当前游戏可出场的敌人（含 Boss、召唤物，不能只扫主数据表），按体型、兵器、战斗定位挑一个最合适的原神官方原型。名称不必逐字对应；找不到完全对应的不要停画，选最接近的，简要写明借哪些特征。旧绑定是线索，不是批准。
- **对着官方图画。** 固定原作图鉴、官方图或官方视频的具体画面，记录链接；记录 2–4 个在战斗大小仍认得出的要点，再直接拟合轮廓、材质和主色。项目旧衍生稿只可作比较，不当作原作证据；不凭空混搭物种或新增饰件。原作图只用于参考，不接为运行时贴图。
- **开画先定上限，再用大色面。** 简单小怪以 **44 总绘图控件**起步（例如 41 图元＋3容器），复杂持械、装甲怪以 **119 总绘图控件**起步（例如 115＋4）；两档都包含实际用到的全部绘图容器和分页。不含生命、意图等战斗 HUD，生产池和同屏总数另量。超档先在原上限内挪预算、充分修形，再记录确实缺什么以及建议预算；不得自动把超档稿当可量产。早期蕈兽119／火法师269／岩盾205只有超档对照价值。

## 2. 图元如何画

- 主剪影先画连贯大面，再加材料的亮／暗面。用原生椭圆保曲面、矩形画直边、必要时才用三角。一块多边形不是一个控件：必须按输出原生行统计，两半三角也算两只。
- 机械/怪物的对称甲片可共享源定义并镜像，但方向性装饰（脸、破损、手持物）单独处理；镜像一般不会减少正在渲染的控件数。
- 重复怪物共享绘图定义和模板。每个活体的变换、血条、命中框、状态、受击与死亡仍独立；不要用一个共享的活动控件承载两只怪。优先动少数父容器，不逐图元重画。
- 用已认可的较高档和一个明显偏弱的低档夹住回合，选中点。同一上限先充分优化：省次要阴影去补关键轮廓；同档仍过不了才考虑调预算。达到实战质量就停；不为减少个位数控件破坏造型。不保证预算与视觉严格单调，需看实物对照。

## 3. 单只验收，随后试点扩批

1. **同尺寸图审**：约 127px（同时按每怪实际锚点/显示比例复核），同背景、同身高/脚底、源图／上轮／这轮并排。先审剪影、脸/眼、重点结构与可见性；只拿大图截图不算通过。记录“保留还是换档”和实际取舍。
2. **离线计数**：记录原生行数、容器、总实际创建数；用仓库现成原生控制器运行创建、120次静止姿态、暂停回访、完整释放。静止无逐图元写入和重建，释放归零。再用真正的怪物 Host 把同屏多只、命中/受击改色、死亡淡出和离场分开计；静止姿态结果不能替代这些。
3. **生产池检查**：正式默认 monsters 关闭。可选怪物装配仍在筛启用资产前按整个目录最大值预留 600 槽，即使换成44/119也不会自然减少。接入时先在独立开发分支对实际启用资产/实例容量定池，测试首现、两只/三只同屏、召唤、变身重绑定、分配失败、解绑/重进；保留对完整保留目录的校验、未启用资产及关闭开关的原回退。**分别记录绘图控件数、生产 actor 及同屏实际总数**，不要相加或用一个冒充另一个。
4. **逐批放量**：先用这两只对接原生与设备，不批量开关全库。不改变已有怪物逻辑；检查命中、HP/意图、动作层序、原生读回、PC/手机和峰值。只有同一候选设备证据过关，再按小批次扩量。画面认可、运行时验证、设备/官方容量通过分别写状态。
