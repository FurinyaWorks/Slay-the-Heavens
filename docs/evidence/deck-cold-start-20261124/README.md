在同一云端 Linux x64、Intel Xeon Platinum 8573C、LuaTeX 1.18 和 Node 24.19.0 上，运行基线及候选的实际 `abyss_ui.lua`、Host 及 `OnUpdate`。走地图上的真实牌组入口和返回按钮。两侧使用基线的同一套原生控件替身、分段模板绑定及已就绪的肖像替身。生成配置是 `--official-assets --native-page-lifecycle --refined-release-monsters`，1280×720，卡图使用现有静态资源。每次新建 Host，确认首开前卡面池零分配。六个独立进程批次交替交换 A/B 顺序。10 张和 75 张场景每臂各 36 个冷开和 36 个随后暖开样本，75 张场景观察当前页 10 个槽。

## 调度压力与资源

另以确定性时钟每次预算检查推进 2.1 ms。在现有 4 ms 预算下，每轮最多两个准备原子。该实验每臂六个 75 张样本，无额外睡眠或 CPU 工作。基线首次冷开首卡和全页均为第 42 轮，黑罩持续 42 轮，其中 17 轮显示准备提示。候选第 0 轮露出牌区，第 10 轮提交首张完整卡，第 42 轮全页就绪，黑罩和准备提示均为零轮。该场景固定准备步数以验证顺序与遮挡。 [逐样本记录](timing.tsv)

两侧每个 75 张 Host 的首次浏览各建 10 张实体和 50 个分段，暖开与随后的 20 次打开关闭均无新建和销毁。关闭时各保留 3,773 个牌组节点、47 个监听、10 个实体，替身中的动态卡图控件为零。候选未增加后台创建入口。 [资源记录](resource.tsv)

采用方案 A。现有预热实验把约 5.95 ms 的 CPU 工作搬到空闲期，首开中位数由 11.83 ms 降为 6.09 ms，两段合计约持平，首次打开前驻留节点由 544 个升为 3,704 个。现有证据还缺乏可安全用来预热的官方客户端空闲窗口。 [原预热实验](../deck-pages-20261122/performance-review.md)

## 官方客户端验收

基线首次打开见到遮罩和准备提示、重复打开正常，来自任务提供的官方客户端黑盒反馈。候选在本次云端未做官方导入或真机渲染。离线轮数与执行时间不直接对应设备帧呈现、首次反馈 P95、卡图实际显示或客户端内存。首反馈 P95 ≤100 ms、冷开首完整卡、全页和暖开基线对照均需同设备实测。

在同设备、相同画质和候选配置下，逐次记录入口输入、牌组框架的首帧、牌区首次无遮挡的帧、首张完整卡的首帧和当前页全部卡牌出现的首帧。每臂至少各 30 个冷开和紧随其后的暖开，冷开重置本次浏览池。按画面帧时间和输入时间求差并报 P50/P95，记录设备、候选身份和采样率。慢加载样本同时验证实际黑罩、返回及快速重开。

## 独立审查

- 产品审查核对现有布局和短暂不可点的详情，发现后续新卡根可能在已显示的牌区内露出空壳。候选将分段模板根设为默认隐藏，回归验证了生成模板和可见卡面。
- 性能审查独立执行本页的交错采样、确定性调度和 20 次资源循环。
- 架构审查核对正式静态模板的启用范围、持有底层页面的就绪边界和选牌保护，并用精确基线复现了候选的历史源码身份漂移。测试入口用完整指纹和反向改动接回原基线。
- 生命周期审查独立验证加载中返回、快速重开、过期触点、排序翻页、切换 Run 和部分显示后失败恢复。原生可见性回调重入可使旧写晚于新页面，候选修复了牌区可见性和遮罩恢复，并加入回归。

## 复跑

用下列命令从基线和候选工作树分别生成 UI。两侧都需要 Git LFS 资产与 Node 22 或更新版本。将 `OUT` 指向各自的输出目录。

```sh
npm ci --ignore-scripts
node scripts/build-lua-data.mjs data "$OUT/abyss_data.lua"
node scripts/build-ui.mjs "$OUT" --official-assets --native-page-lifecycle --refined-release-monsters
```

再用 LuaTeX 和 Python 3.10 或更新版本运行交错矩阵。

```sh
python run-matrix.py "$BASE" "$CANDIDATE" "$BASE_UI" "$CANDIDATE_UI" \
  --out "$RESULTS" > "$RESULTS.summary.tsv"
```
