# 正式牌堆浏览与圆角按钮验收记录

基线为 develop `73fd14aab04c590037c39197364f725a767fed19`。候选生产代码为 `2634d7b69aec314948628be03069f56ac5bb71de`。前后使用同一官方 UI 构建参数与 `tests/benchmarks/pile_browser.lua`。LuaTeX 在同一个 CPU 核上运行项目真实 Lua。控件由仓库原生 API 合同夹具提供。四种牌堆分别使用 7、20、75、250 张真实定义的卡牌实例。每种规模分别测 30 个冷 Grid、同 Grid 重开以及排序回调。

[完整 P50/P95 数据](timings.csv) 中的 `total_ms` 为输入回调到首屏通过 Lua 就绪检查的累计 CPU 时间。冷开包括两次 Grid 刷新，校准后的首屏在第一个模拟更新完成。热开、排序同步提交。内存列是采样区间内 Lua 堆差值，包含夹具分配，不能推导常驻内存。Grid 计数为夹具回调数，校准仍需一次回调，候选在该回调里只取索引。首屏保留卡位数前后相同。表中的快照、投影、Host 刷新、Grid 工作与卡面填充时间来自同一调用路径。排序 CPU 单列，包含在快照或投影的计时内。

冷开的主要 CPU 开销仍来自 Grid 模板创建和卡面填充。抽牌四组的标题几何检查由第一个模拟更新提前到输入回调结束，卡位就绪仍为第一个模拟更新。排序和热开在同一次回调提交。这里的标题检查验证文字区域未被遮挡，原生输入采样、帧提交、GPU 绘制、实际内存和设备端到端延迟均待实测。准备时沿用原就绪门的输入阻挡，真实设备上还需验证多次快速点击在异步刷新期间的表现。
