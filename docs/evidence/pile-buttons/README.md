# 正式牌堆浏览与圆角按钮验收记录

基线为 develop `73fd14aab04c590037c39197364f725a767fed19`。候选使用同一官方 UI 构建参数与 `tests/benchmarks/pile_browser.lua`。LuaTeX 在同一个 CPU 核上运行项目真实 Lua。控件由仓库原生 API 合同夹具提供。四种牌堆分别使用 7、20、75、250 张真实定义的卡牌实例。每种规模分别测 30 个冷 Grid、同 Grid 重开以及排序回调。

[完整 P50/P95 数据](timings.csv) 中的 `total_ms` 为输入回调到首屏通过 Lua 就绪检查的累计 CPU 时间。冷开包括两次 Grid 刷新，校准后的首屏在第一个模拟更新完成。热开、排序同步提交。内存列是采样区间内 Lua 堆差值，包含夹具分配，不能推导常驻内存。Grid 计数为夹具回调数，校准仍需一次回调，候选在该回调里只取索引。首屏保留卡位数前后相同。表中的快照、投影、Host 刷新、Grid 工作与卡面填充时间来自同一调用路径。

| 抽牌堆卡数 | 冷开 P50/P95 ms | 热开 P50/P95 ms | 排序 P50/P95 ms |
| --- | --- | --- | --- |

| 20 | 19.93/22.41 → 18.11/22.13 | 4.10/5.03 → 2.42/3.05 | 4.30/5.96 → 3.98/4.89 |

| 250 | 24.47/26.14 → 19.42/23.54 | 8.76/13.29 → 3.13/4.79 | 7.58/8.68 → 4.88/6.63 |

75 张的冷开及排序尾部出现回退，冷开时 Grid 模板创建和卡面填充仍占用主要 CPU。原生输入采样、帧提交、GPU 绘制、实际内存和设备端到端延迟未实测。牌堆准备框使用原有就绪门的 Grid 区域，标题、工具栏和返回位于框外。
