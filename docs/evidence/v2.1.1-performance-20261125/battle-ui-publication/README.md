## 根因与修复

| 追问 | 怪物意图粒子 | 隐藏战斗页 |
| --- | --- | --- |
| 为什么有重复工作 | `updateEnemyIntents → paint` 在每个存活粒子上重复查找并写入可见性、图源、尺寸、图标局部位置和固定角度。 | 每次开关选角都经过 `GameUI.refresh → battleUI:setActive(false) → render`，连刚清空的战斗页也重新投影。 |
| 为什么既有机制不能消除 | `Surfaces.select` 维护控件、层序和生命周期，没有记录粒子外观成功发布。 | `active` 只反映当前显隐。弃局会先清空 Run，已投影的 Run、战斗、反馈和输入状态仍需一次完整退役。 |
| 为什么此前优化未覆盖 | #706 在旧 Release 线上实现，当前 Hotfix 源自线上 master 链。当前既有意图文字和几何缓存服务不同控件。 | 既有投影延期覆盖战斗及地图牌组场景。开关选角经过普通页面刷新，无从判断空投影是否完成。 |
| 为什么既有测试没发现 | 旧首战基准缺少此混合粒子负载。粒子测试覆盖画面、时钟和回收，未断言同值写入。 | 生命周期测试断言输入、显隐及状态正确。旧基准没有连续关闭重开选角，也不记录 `GetChild`。 |
| 如何防止再次回归 | 从既有池退役回调撤销绑定。写入成功且代次有效才保存外观。固定写入、原生漂移和动画、拒绝、重绑及销毁均有断言。 | 选角关闭或 Run 已弃局后，先完成一轮空投影，再以渲染代次、展示所有权及原生显隐读取确认可以复用。拒绝的显隐、旧 Run 和反馈所有权保留重绘。定向用例逐一注入拒绝，并覆盖暂停继续、反馈退出、长按和旧回调。 |

粒子视图绑定固定外观。每个存活原生实例只保留一份外观记录，依现有池回收。保留 STUN 旋转、缩放、色彩、根位置、显示门限及层序更新。组件读取发生重入时检查代次，同所有者重入后丢弃可能重叠的缓存记录。战斗规则、更新步长和随机数调用路径保持原样。 [粒子视图](../../../../src/lua/abyss_monster_intent_particle_view.lua)

战斗动作复用已有完整渲染代次。每次停用仍执行根控件显隐和输入取消。首次进入选角继续走完整渲染，选角实际关闭或弃局后启用复用资格。旧 Run、显示战斗、反馈、手势及提示仍有所有权时执行完整投影。原生显隐读取期间逐次检查代次和引擎生命周期，同所有者重入改走完整投影。拒绝隐藏的奖励行、手牌和消耗堆会在后续刷新重试。 [战斗动作](../../../../src/lua/abyss_battle_actions.lua) · [选角](../../../../src/lua/abyss_game_ui_run.lua) · [导航](../../../../src/lua/abyss_game_ui_navigation.lua)

## 复验与边界

初版通用渲染包装在 0.5 CPU／1 GiB 下触发暖 Host 和开局进地图时序差异。干净构建的单变量复跑将持续信号定位到隐藏页切片，未在同源码 A/A 和粒子单项复现。每阶段进程 CPU 与带标记的 V8 日志也捕获到同段 CPU 增量和更多 Fengari 执行器 deopt。该证据限于离线解释器。最终实现把空投影复用限于首次选角实际关闭或弃局后的页面转换。通用渲染和原显隐写入源码逐字节保持 BASE。相对较宽的早期试验，最终版本用受生命周期保护的直接读取确认控件状态。失败版本、推迟读取版本及其他实验的补丁、原始值和源码标识均收录于诊断档案。
