2. 每阶段使用已审干净工作树。B0 以 `73c21489efaab409d4c0c46bee517d410d3427fc` 起步。B1 接入 B 的四职业完整候选，B2 在 B1 上对接 C 的第三幕玩法，B3 在 B2 上逐批接已批准且完成映射核对的第三幕美术。逐阶段记下完整源 SHA、真实有效开关、实际模块和美术绑定摘要。用 `git diff` 和最终独立读回确认每轮只增加指定阶段的变量。若新开关使阶段应有内容未写入，或关闭入口仍序列化内容，记录准确清单并修正对照。
3. 待各阶段可经正式构建入口生成时，在每个固定工作树根目录使用同一配方及新输出目录。B0 默认生产 profile 为 `official-assets-battle-v3`。B1/B2/B3 的开关以各自实装源码及独立收据为准。合入前实验可以沿用相同参数的非发布配方取得只读对照，整组统一保留该实验模式。

```sh
# STAGE 依顺序取 B0、B1、B2、B3-<批次> 或组合，三项变量使用本轮实际值。
export MILIASTRA_ALLOW_LIVE_WRITE=0
npm run build:native -- "$BASE_GIL" "build/v6-d-candidates/$STAGE" --release-candidate --work-key="$WORK_KEY"

  --candidate "$FINAL_GIL" --receipt "build/v6-d-candidates/$STAGE/audio/candidate.json" \
  --output "build/v6-d-audits/$STAGE" --bgm
```

4. 保留终端给出的最终音频 `candidate.json` 及其 `mapPath`，将后者填入 `$FINAL_GIL`。核对精确 `sourceCommit`、`buildId`、`candidate.sha256`、`payloadDigest`、实际 `productionManifest`、官方写入后读回和底图、音频及资源开关。在交接路径重算 GIL SHA-256，保留原完整目录。
5. A 轴单独测量获准的零图／单图、单宿主换图、同图增宿主，待通过再测完整 75。Alpha/Production 现行策略会拒绝卡图开启，真实可导入的 A 轴需获批可导入的隔离实验路线。首次从低图元单卡起且设备稳定后，才安排多图、多宿主。最终组合候选同时含 A3 和最后一批 B3 再测。
