## 验收合同

1. 首次进入仅开放 A0。正常随机开局在第二幕正式胜利后，若本局难度等于该角色当前最高解锁难度，则推进一档。A14 记录最高通关并封顶。按角色隔离、重复结算幂等，失败、放弃、低难度重试和指定种子均不推进解锁。指定种子挑战不计正式成就。
2. 保持 A0 原行为和已有固定种子回归。每档叠加前档，明确 A1 比率与取整、怪物独立差异、A5 缺失生命恢复、A6 取整、各幕升级奖励概率、Boss 金币及 A14 的角色差异。岩旅行者初始生命用 `80/80`、`72/80`、`68/75` 交叉校验，原版证据确定精确结果。
3. 同版本、角色、难度、种子、相关初始状态及操作序列时，业务随机复现。记录开局祝福、Boss 历史与内容解锁的影响。UI、动画、日志和预览使用其各自的表现状态。对玩家指定种子验证无损输入、展示、解析及重复开局，兼容既有开发回放。
4. 存档在官方平台通过真实离场、重新进入、按角色读取、旧存档迁移、失败恢复及重复结算。旧档采用可追溯进度，更新须幂等且随进度单调。
5. 默认关闭时核对入口、规则、解锁、启动与性能。集成验收后对 v2.3.0 候选开启并复验同一交付包。容量记录 19MB 内部控制线和 20MB 平台硬限，绑定正式 Full CI、GIL SHA-256、导入、当前 ready、PC、实体手机与实际性能证据。独立验收包括代表性难度的两幕自然胜利。

## 发版门禁

日常切片按 [Fork-First 与小批量集成](../TASK_EXECUTION.md) 和 [现有 CI](../CI.md) 交付至 `develop`。每个提交保留任务、验证命令、独立评审及精确来源。v2.2.0 的 Release 流程独立执行。

- 准入核对已合入的范围、生产祖先关系、依赖与独立验收。记录候选源码、配置、源码树及有效验证。
- 正式上线核对同一有声 GIL、完整 CI、设备与官方证据并更新玩家 ChangeLog。由 Owner 确认并操作官方发布。
- 发布后登记真实平台版本、归档及凭证，按 [版本治理](GOVERNANCE.md) 完成回流，核对实际生产提交和合后验证。
