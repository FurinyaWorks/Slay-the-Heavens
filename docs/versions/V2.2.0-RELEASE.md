## 三道门禁

1. **Release 准入。** 审定范围与延期、必要 PR 已集成、master 完整回流，确认 develop 精确提交的适用 CI 与切分基线。通过后从该提交创建 `release/v2.2.0`。冻结后只接必要缺陷修复，例外在本规划和 Backlog 记录批准者、理由、影响与门禁复验。新增需求进入后续版本。
2. **正式上线。** 完成下表中的冻结候选审计、完整 CI、同包真实性能及各设备验收，执行 [发布操作单](../PUBLISHING.md) 的当前 HEAD 检查，经独立评审与 Owner 确认后由 Owner 操作官方发布。
3. **发布后结项。** 归档平台实发版本、凭证、工程 Tag、GIL 和原始证据。Release 或 Hotfix 合入 master 后，以保留祖先关系的合并将生产提交完整回流 develop，复核实际继承和合后 CI，再关闭版本主任务。
