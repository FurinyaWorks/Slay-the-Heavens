# ADR 0001 双人联机与高精度图元技术规范

日期 2026-11-19。状态 **已接受**。平台与设备验证进度见文末。跟踪 TASK-109，继承 [TASK-33](../backlog-details/TASK-33.md) 和 [DRAFT-3](../backlog-details/DRAFT-3.md) 的真实双端验收要求。

## 背景与产品范围

《Slay-the-Abyss》（《杀戮原塔2》）是原神千星奇域回合制卡牌 Roguelike。正式产品范围为 **1–2 名真人玩家**。千星奇域经典模式最多 4 人，超限模式最多 8 人。两人为项目主动选择。双人合作候选须在实际关卡或房间中设置并读回最小 1 人、最大 2 人，验证单人启动、第二人加入、第三人被平台拒绝。席位和稳定的 `playerId` 与场上可见角色独立建模，单人无需两名可见角色。人数上限集中配置。保留已发布单人入口，双人通过验收后再作为完整玩法接入。 [千星奇域《综合指南》](https://act.mihoyo.com/ys/ugc/tutorial/detail/mh29wpicgvh0)

优先把元素反应、卡牌协作、资源管理、回合配合和策略深度做成独立合作体验。本决策的排除项为三至四人玩法及其布局和同步、按人数自动降精度、四人专用 Q 版或像素替代系统，以及面向四人预建的架构。

2026-07-16 发布的社区样本共计 832,208 条提交记录，其中多人 327,636 条。多人占比由原文各组记录数计算。 [Spire Codex 合作指南](https://spire-codex.com/guides/coop-guide)

| --- | ---: | ---: | ---: |
| 单人 | 504,572 | — | 19.1% |
| 双人 | 177,807 | 54.3% | 23.6% |
| 三人 | 92,996 | 28.4% | 46.9% |

## 平台容量与计量

外部 PNG/JPG 用作参考源图。按仓库已验证的拟合和转换路径生成平台可用图元或绘制实现，原始图像不得作为任意运行时 UI 贴图加载。`.gia` 是资产交换格式，客户端 UI 实例按实际装配生成。按平台实际资源类别分别登记场景实体、素材组、界面布局、传统 UI 控件组、模板和客户端动态实例。 [官方资产导入导出](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhxbd59urbfu)

| 项目 | 官方上限 |
| --- | ---: |
| Interface Layouts | 100 |
| Custom Control Templates | 2,000 |
| UI Controls Within a Single UI Control Group | 1,000 |
| UI Controls Displayed on Player Screen at One Time | 10,000 |

10,000 是官方容量上限。流畅度由实际设备独立验收。预算以最终运行时实例为准，包括描边、渐变、发光、叠层和容器开销。7.1 客户端容器和动态节点在官方配额中的归属须实测。角色父容器提供独立生命周期；传统控件组的计数归属须另取证。禁止利用未知嵌套行为绕开平台限制。 [官方 Edit Range Restrictions](https://act.hoyoverse.com/ys/ugc/tutorial/detail/mh74ae9fsg8i)

## 角色、卡牌与单端预算

同一角色和参数化生成管线提供 300 图元低精度对照、400 图元基础基准、600 图元高精度候选。600 需要可见画质收益与真机合格两项证据。战斗手牌使用平台可用素材、预设图标、文字和边框，简化卡面预留每张 15–40 个控件。复杂手牌拟合插画需等角色性能验证通过。

| 模块 | 轻载 | 目标 | 峰值 |
| --- | ---: | ---: | ---: |
| 两名可见角色 | 600 | 800 | 1,200 |
| 四只怪物 | 400 | 600 | 800 |
| 十张手牌 | 200 | 300 | 400 |
| HUD | 150 | 200 | 300 |
| 临时特效/UI | 150 | 400 | 500 |
| **单端总计** | **1,500** | **2,300** | **3,200** |

初始按一图元对应一控件估算。最终须以实例清单登记实际开销，并列出额外 UI、隐藏实例和瞬时重叠峰值。每个客户端分别记录创建和同屏数量，报告 A、B 两种视角。十张卡片为本端手牌，队友预览或共享手牌另计。2,300 是目标测试配置。

## 实现与权威同步

角色、敌人、手牌、HUD、特效独立管理。静态保留高精度图元，通过经验证的父容器变换或原生 Tween 实现呼吸、攻击、受击和位移，避免逐帧遍历数百图元。通过平台文档或最小实验核实 API。退出入口、聊天和手牌交互须可用且不受立绘遮挡。仅使用原创或适当授权美术。

可信服务端或平台权威节点图独立持有共享战斗状态，提交伤害与状态、抽牌与随机、回合、共享资源和胜负。客户端仅发送操作意图、应用权威视图和播放效果。复用现有节点图通路；当前 [本地战斗](../../src/lua/abyss_combat.lua) 仍在客户端执行，[服务端结算图](../../scripts/settlement-graph.mjs) 只收胜负信号，尚不能作为战斗权威。合作切片需先验证可信发件人识别、定向视图、事件顺序与平台数据表示能力，再确定最小战斗迁移范围。

至少验证真实双端状态一致、两个席位同时输入、重复/过期/乱序意图、超时、退出和重连。记录每位玩家的牌组、手牌、能量、血量归属及可见性，以及共享敌人、地图、回合、随机、奖励和资源。重连策略按实际平台能力决定。

## 验收与证据

- **容量**。同基线隔离测试单组 999、1,000、1,001、1,100，多控件组、客户端嵌套容器和动态模板。保存最小复现、编辑器与运行时版本、创建数、同屏显示数、日志、测试动作和结论。分别判断硬性限制、API 拒绝、脚本超时和性能退化。
- **拟合**。输出同源三档对照、原始图元数、最终实例、每组数量、布局或场景的创建数、同屏峰值和工件身份。按画质改善及真实设备成本选型。
- **手机**。用同一候选在固定的目标中端手机、画质、分辨率、测量方式和测试时长下，分别采集 A/B。覆盖静态站位、双人攻击和受击、抽牌出牌、四怪同屏、特效峰值、连续战斗切换。持续 ≥30 FPS，P95 帧时间 ≤33.3 ms；另记录 P99、卡顿次数、内存峰值、加载耗时、客户端脚本或节点图更新时间、可测的布局和绘制开销。保留官方负载检测开与关的对照，上线前执行官方风险检查与负载检测。 [仓库负载证据合同](../PLATFORM_LOAD.md)
